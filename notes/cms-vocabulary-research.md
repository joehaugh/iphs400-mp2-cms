# CMS vocabulary: WordPress, Drupal, static-site generators

Research for IPHS 400 Mini-Project #2. Primary sources only (official docs). Retrieved 2026-10-12.
Items I could not confirm on a primary page are marked **UNVERIFIED**.

## Summary

- All three families separate three concerns: what content looks like (content model), who may do what (users, roles, permissions), and when it becomes public (publishing).
- WordPress and Drupal are dynamic: content lives in a database and pages are rendered per request. WordPress stores every post type in one table (https://developer.wordpress.org/themes/basics/post-types/).
- Static-site generators (SSGs) have no users or database. Content is Markdown files with front matter metadata, and the "publish" step is a build that writes HTML files (https://gohugo.io/getting-started/directory-structure/, https://www.11ty.dev/docs/).
- Our CMS is a hybrid. It has a WordPress/Drupal-style admin (users, roles, draft/published in SQLite) and an SSG-style output (build static HTML from published content only).

## Comparison

| | WordPress | Drupal | SSGs (Hugo / Jekyll / Eleventy) |
|---|---|---|---|
| Content model | Post types: post, page, custom post types, all in one table (https://developer.wordpress.org/themes/basics/post-types/). Classified by taxonomies such as categories and tags (same page). | Content entities hold data in fields. A content type is a subtype of entity for main page content (https://www.drupal.org/docs/user_guide/en/planning-data-types.html). | Files with front matter. Hugo infers content type from the top-level directory or a `type` field (https://gohugo.io/methods/page/type/). Jekyll groups content in collections (https://jekyllrb.com/docs/collections/). Eleventy groups content by `tags` into collections (https://www.11ty.dev/docs/collections/). |

Roles can be added with `add_role()` and capabilities changed with `add_cap()` (https://wordpress.org/documentation/article/roles-and-capabilities/). | Users get roles. Roles group permissions. Permissions are defined by modules (https://www.drupal.org/docs/user_guide/en/user-concept.html). | None built in. Access control is whoever can edit the repo or files. **UNVERIFIED** (absence of a feature is not stated in the pages I read). |
| Publishing workflow | Post status values: publish, future, draft, pending, private, plus trash, auto-draft, inherit (https://developer.wordpress.org/reference/functions/get_post_status/). | Core has published/unpublished. ## Glossary

| Term | WordPress | Drupal | SSGs |
|---|---|---|---|
| **Content type** | Post type (post, page, custom). https://developer.wordpress.org/themes/basics/post-types/ | Content type, an entity subtype for main-page content. https://www.drupal.org/docs/user_guide/en/planning-data-types.html | Hugo: "a classification of content inferred from the top-level directory name or the `type` set in front matter" (https://gohugo.io/quick-reference/glossary/). Jekyll: collections (https://jekyllrb.com/docs/collections/). |
| **Field** | Not covered on the pages I read. **UNVERIFIED** | "Within entities, the data is stored in individual fields" (https://www.drupal.org/docs/user_guide/en/planning-data-types.html). | Front matter: "metadata at the beginning of each content page" (https://gohugo.io/quick-reference/glossary/). |
| **Slug** | Post slug: the sanitized title, e.g. "This Is A Great Post!" becomes `this-is-a-great-post` (https://wordpress.org/documentation/article/customize-permalinks/). | URL alias gives content a friendlier path than `node/7` (https://www.drupal.org/docs/user_guide/en/content-paths.html, via search snippet). | Hugo `slug` "overrides the last segment of the URL path" (https://gohugo.io/content-management/front-matter/). Jekyll has a `:slug` placeholder (https://jekyllrb.com/docs/permalinks/). Eleventy uses a `slugify` filter (https://www.11ty.dev/docs/permalinks/). |
| **Draft / published** | Statuses `draft` and `publish` (https://developer.wordpress.org/reference/functions/get_post_status/). | Unpublished/published; a moderation state marked "published" sets the core status to published (https://www.drupal.org/docs/8/core/modules/content-moderation/overview). | Hugo `draft`; Jekyll `_drafts` (sources in the table above). |
| **Role** | One of six predefined, e.g. Editor "can publish and manage posts including the posts of other users" (https://wordpress.org/documentation/article/roles-and-capabilities/). | "Permissions are grouped into roles" (https://www.drupal.org/docs/user_guide/en/user-concept.html). | No equivalent. |
| **Capability** | A task a role is allowed to perform, e.g. `publish_posts`, `edit_users` (https://wordpress.org/documentation/article/roles-and-capabilities/). | Called a **permission**: "the ability to do actions on your site... is governed by permissions" (https://www.drupal.org/docs/user_guide/en/user-concept.html). | No equivalent. |
| **Permalink** | "The permanent URLs of your posts, pages, categories" (https://wordpress.org/documentation/article/customize-permalinks/). | Path plus URL alias (https://www.drupal.org/docs/user_guide/en/content-paths.html, via search snippet). | Jekyll: "the output paths for pages, posts, or collections" (https://jekyllrb.com/docs/permalinks/). Eleventy: controls where a template is written in the output directory (https://www.11ty.dev/docs/permalinks/). **Hugo uses the word differently**: a permalink is "the absolute URL of a published resource" (https://gohugo.io/quick-reference/glossary/). |
| **Taxonomy** | Categories and tags classify posts (https://developer.wordpress.org/themes/basics/post-types/). | Taxonomy classifies content. A set of terms is a vocabulary (https://www.drupal.org/docs/user_guide/en/structure-taxonomy.html). | Hugo: "a group of related terms used to classify content" (https://gohugo.io/quick-reference/glossary/). Jekyll: tags and categories (https://jekyllrb.com/docs/posts/). Eleventy: tags build collections (https://www.11ty.dev/docs/collections/). |
| **Theme** | "The design of your website... colors, fonts, the entire layout" (https://developer.wordpress.org/themes/getting-started/what-is-a-theme/). | Files defining look and feel; it supplies the HTML markup and CSS around content (https://www.drupal.org/docs/user_guide/en/understanding-themes.html, via search snippet). | Hugo: "a module that delivers a complete set of components defining a site's layout" (https://gohugo.io/quick-reference/glossary/). Jekyll: packages assets, layouts, includes, stylesheets (https://jekyllrb.com/docs/themes/). Eleventy uses layouts (https://www.11ty.dev/docs/layouts/). |
| **Headless** | Use the REST API to bring content "into completely separate applications" (https://developer.wordpress.org/rest-api/). | Core JSON:API module gives RESTful CRUD for content (https://www.drupal.org/docs/core-modules-and-themes/core-modules/jsonapi-module). The page's "decoupled" framing is my summary. | **Warning**: Hugo's "headless bundle" means an unpublished bundle, not a headless CMS (https://gohugo.io/quick-reference/glossary/). In the CMS sense, an SSG is the front end of a headless setup. **UNVERIFIED** from SSG docs. |

## Takeaways for our CMS

- **Admin vs editor.** Use the WordPress shape: role holds capabilities, code checks the capability rather than the role name. WordPress notes that no role is "senior"; roles define responsibilities (https://wordpress.org/documentation/article/roles-and-capabilities/). A minimal pair: `admin` (manage users and everything) and `editor` (write and publish content). WordPress's Contributor, who can write but not publish, is the model if you want a review step (same source).
- **Draft / published.** Keep a single status column with two values. Only `published` rows get rendered. This matches WordPress `draft`/`publish` and Hugo's rule that drafts are not rendered by default (sources above). Drupal's moderation shows a model where a state maps to a published flag, so more states can be added later without changing the render rule (https://www.drupal.org/docs/8/core/modules/content-moderation/overview).
- **Slug and permalink.** Store a slug per item, derived from the title but editable and unique. Treat the permalink as the output path built from the slug (Jekyll and Eleventy both define it as output location). WordPress says permalinks "should never be changed" (https://wordpress.org/documentation/article/customize-permalinks/), so decide whether renaming a slug is allowed after publish.
- **Relative-path static output.** Eleventy's default writes `slug/index.html` so URLs stay stable (https://www.11ty.dev/docs/permalinks/). Hugo has a `relativeURLs` option for sites served without a server, and its docs say it is "useful for serverless sites only" (https://gohugo.io/content-management/urls/). Our repo rule (relative paths only) is the same idea. Compute each page's depth from the output root when rendering links.
- **Vocabulary.** Prefer: content type (maybe just "page" and "post"), slug, status (`draft`/`published`), role, capability, permalink, theme (the Jinja templates). Skip taxonomy unless a ticket needs it.
